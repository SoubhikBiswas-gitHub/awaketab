# 07 · Internationalisation (i18n)

Status: v1.0 · 2026-09-07 · Owner: Soubhik

**Purpose.** How AwakeTab ships in eight languages at launch without the machine-translation tells that undermine the competitors: routing, string files, formatting, translation workflow, localized keyword research and the QA bar. Localization is an SEO investment as much as a UX one — each locale is a separate results page we can win.

Related docs: `00-conventions.md` §7 (locales, routes) · `05-frontend-spec.md` (where strings render) · `06-content-seo-spec.md` (hreflang, translated slugs, per-locale sitemaps) · `13-testing-strategy.md` (missing-key test).

## 2. Astro configuration

```js
// apps/web/astro.config.mjs (excerpt)
export default defineConfig({
  site: process.env.PUBLIC_SITE_URL ?? 'https://awaketab.com',
  i18n: {
    defaultLocale: 'en',
    locales: ['en', 'es', 'pt-br', 'de', 'fr', 'ja', 'zh', 'hi'],
    routing: { prefixDefaultLocale: false, redirectToDefaultLocale: false },
    fallback: {},               // no fallback pages — an untranslated page does not exist in that locale (no thin duplicates)
  },
});
```

Rules: a locale page exists only when its content is translated and reviewed; the hreflang set for a page lists only existing translations (`06-content-seo-spec.md` §5). Never auto-redirect by `Accept-Language`; show a one-time, dismissible suggestion banner ("Read this in Español?") stored in `at.v1.onboarding.dismissedTips` as `lang-suggest`.

## 3. UI strings

### 3.1 Files and loader

`apps/web/src/i18n/{locale}.json` — flat JSON with dot.case keys grouped by screen. Loaded at build for static markup and bundled per locale for the island (only the active locale ships: ≈ 6 KB gz). Extension strings live in `apps/extension/src/i18n/` with the same keys and a `_locales/` export for the store listing.

Library choice: **`@formatjs/intl-messageformat` is too heavy for the 40 KB budget; use `intl-messageformat`'s lightweight sibling `@messageformat/core` at build time to pre-compile ICU strings into functions**, so the runtime is a 1 KB `t(key, vars)`. Decision recorded as ADR-013 (see `03-architecture.md` addendum): ICU syntax for authors, compiled functions in the bundle, zero runtime parsing.

```ts
// apps/web/src/tool/i18n.ts
export const t = (key: MessageKey, vars?: Record<string, string | number>): string
export const locale: Locale            // from <html lang>
export const fmt = {
  time(d: Date, opts?: { seconds?: boolean }): string     // Intl.DateTimeFormat, honours settings.ambient.clock24h
  duration(ms: number): string                              // "1 h 30 min", "45 s"; locale-aware units via Intl.NumberFormat unit style where supported
  date(d: Date): string
  number(n: number): string
}
```

## 4. Formatting rules

| Concern | Rule |
|---|---|
| Times | `Intl.DateTimeFormat(locale, { hour, minute })`; 12/24 h follows the locale unless `settings.ambient.clock24h` overrides |
| Durations | Compose from units with `Intl.NumberFormat(locale, { style:'unit', unit:'hour'|'minute', unitDisplay:'short' })` where supported; fallback strings per locale |
| Countdown digits | Always `tabular-nums`, always Latin digits (`numberingSystem: 'latn'`) — Hindi and Arabic UIs keep Latin digits for the timer |
| Plurals | ICU `{n, plural, …}` — never string concatenation |
| Dates in stats | `Intl.DateTimeFormat(locale, { month:'short', day:'numeric' })` |
| Text length | Assume German/French +35%, Hindi +20%; chips wrap to two rows at 320 px; the pill truncates never (it scrolls on one line with `text-overflow: clip` disabled — copy is short by design) |
| Product terms | `AwakeTab`, `Pro`, `Wake Lock` untranslated; "Cook Mode" translated |

## 5. Content translation workflow

1. **Source** — English MDX is finished, fact-checked against `src/data/support-matrix.json`, and has `lastVerified`.
2. **Brief** — the translator receives: the page's `intent` query in English, the localized target query (from §7), the audience, the honest-limit callout (must not be softened), a glossary, and the UI screenshots.
3. **Translate** — into `src/content/{collection}/{locale}/{slug}.mdx` with `translationOf: "<en-slug>"`; translated slug (Latin-script locales only) added to `src/i18n/slugs.json`.
4. **Native review** — a native speaker reviews against the QA checklist (§8); reviewers are paid contractors (budget in `01-brd.md`).
5. **Publish** — build adds hreflang pairs automatically for every existing translation; sitemap alternates update.
6. **Maintain** — when the English source changes `lastVerified`, translations are flagged stale (`translationOf` + hash comparison at build → warning list) and re-queued.

Machine translation may produce the first draft; it never ships without step 4. The ~1,200-word home page and the top 10 pages (`/for/cooking`, `/for/downloads`, `/for/presentations`, `/on/iphone-safari`, `/on/android-chrome`, `/on/windows-11`, `/on/macos`, `/guides/iphone-auto-lock-never-greyed-out`, `/vs/caffeine`, `/learn/browser-support-matrix`) are translated first.

## 6. RTL readiness (phase 2, Arabic)

Use logical properties everywhere now (`margin-inline-start`, `padding-inline`, `inset-inline-end`, `text-align: start`). The ring, the progress direction and the heatmap are direction-neutral. `dir="rtl"` set on `<html>` per locale; icons that imply direction (chevrons) flip via `[dir=rtl] { transform: scaleX(-1) }`. No layout work is required later if these rules hold from day one — enforced by a stylelint rule banning physical properties.

## 8. Translation QA checklist (native reviewer)

- [ ] Meaning matches the English source, including every limit and caveat (nothing softened, nothing promised).
- [ ] Reads as written by a native speaker: no calques, no machine-translation tells (odd articles, literal idioms, inconsistent formality).
- [ ] Product terms untranslated (`AwakeTab`, `Pro`, `Wake Lock`); UI labels match the shipped `{locale}.json` exactly when quoted.
- [ ] Title ≤ 60 characters (CJK: ≤ 30 full-width), description ≤ 155 (CJK ≤ 80); H1 targets the local query.
- [ ] Numbers, dates, times and units in local convention; timer digits Latin.
- [ ] Screenshots localized or clearly English with a note.
- [ ] Layout check at 320 px and 1280 px in that locale (no clipped chips, no overflowing pill).
- [ ] Links point to the same-locale page where one exists, otherwise to English with `hreflang` intact.
- [ ] `translationOf`, `lastVerified` and translated slug present.

## 9. CI checks

- Missing-key test: every key in `en.json` exists in every launch locale; every `t('…')` in code exists in `en.json`.
- Placeholder parity: `{vars}` identical between source and translation.
- Length lint: warn when a translation exceeds 1.6× the English length for pill/chip keys.
- Hreflang reciprocity and translated slug uniqueness (`06-content-seo-spec.md`).

## 11. As built — E6-T05, E6-T06, E6-T07 (2026-09-26)

**E6-T05 localized chrome.** OG images per locale page (`06-content-seo-spec.md` §19): CJK and Devanagari render through satori with Noto Sans JP/SC/Devanagari embedded at build only. Web app manifests: `scripts/manifests.mjs` already writes `public/{lang}/manifest.webmanifest` with `name` = `AwakeTab — {app.tagline}`, `description` = `page.home.description`, `lang` = the BCP 47 tag and `id`/`scope`/`start_url` under `/{lang}/`; verified, and now asserted by the SEO suite. JSON-LD `inLanguage` uses `LOCALE_META[locale].hreflang` (BCP 47) on every localized page.

**E6-T06 top-10 translations.** 70 pages, 10 per locale, all `reviewed: false` → `noindex`, out of sitemaps and hreflang until a native reviewer flips `reviewed: true` per page (§2 rule "a locale page exists only when … reviewed" is implemented as "exists, but unindexed and labelled until reviewed"). Workflow step 5 (§5) is automatic: `alternatesFor()` in `apps/web/scripts/translations.mjs` feeds both the page `<link rel="alternate">` set and the sitemap `xhtml:link` set. `translationOf` must equal the file's EN slug (build error otherwise). The stale-translation hash check of §5 step 6 is not built yet. Public slugs: `es`, `pt-br`, `de`, `fr` translate them via `src/i18n/slugs.json`; `ja`, `zh` and `hi` keep the English slug (`/ja/for/cooking`), per `06-content-seo-spec.md` §5 (decision D-03, 2026-09-26, which retired the unindexed romanised slugs of the first build; §19 there has the guards).

**UI strings.** The seven `content.*` keys (`content.verified`, `content.stale`, `content.faq`, `content.related`, `content.start`, `content.author.role`, `content.author.about`) were still English in every locale file; they are now translated. New keys, appended to all 8 catalogs: `content.breadcrumb`, `content.translation.pending`, `content.translation.original`.

**E6-T07 i18n QA.**
- *Pseudo-locale overflow* (`test/e2e/i18n.spec.ts`): the Playwright route rewrites the page's `data-i18n-catalog` JSON so every string is accented and ~40 % longer, and expands every static text node the same way; tool routes and content pages must show no clipped or off-viewport text at 320 px, idle and running. The real locales run the same check without pseudo text. It caught two bugs, both fixed: translated related-link chips overflowing (shadcn button `h-9 shrink-0`) and unbreakable inline `code` in CJK/Devanagari prose.
- *RTL readiness (§6).* `textDirection(htmlLang)` and `RTL_LANGUAGES` (`ar`, `fa`, `he`, `ur`) in `src/i18n/locales.ts` set `<html dir>` in `BaseLayout.astro` — adding `ar` to `LOCALE_META` needs no layout change. Physical Tailwind utilities left in markup were converted to logical ones (`border-s`, `text-start`/`text-end`, `pe-0`), a unit test bans them in `src/components`, `src/layouts`, `src/pages` and `src/tool` (stylelint already covers CSS), and `tokens.css` mirrors direction-implying icons (breadcrumb chevrons, `.at-flip-rtl`) under `[dir="rtl"]`. An e2e check forces `dir="rtl"` on a content page at 320 px.
- *Per-locale smoke*: each locale home and one translated page — `lang`/`dir`, localized `h1`, pill reaches the locale's `tool.pill.held`, zero console errors.

Accepted into `00-conventions.md` §13.17 (owner decision D-04, 2026-09-26): route `/{lang}/{collection}/{public slug}` (translated slug for `es` / `pt-br` / `de` / `fr`, English slug for `ja` / `zh` / `hi`); OG path `/og/{lang}/{collection}/{public slug}.png`; `apps/web/scripts/translations.mjs` (`alternatesFor`, `isIndexable`, `contentPath`, `publicSlug`, `ogImagePath`, `readContentIndex`, `frontmatterScalars`, `TRANSLATED_SLUG_LOCALES`); `apps/web/src/lib/content-i18n.ts`; `RTL_LANGUAGES` / `textDirection()`; `LocaleNav`/`BaseLayout`/`ContentLayout` prop `localeLinks`; `ogImageAlt` prop; `.at-flip-rtl`; i18n keys `content.breadcrumb`, `content.translation.pending`, `content.translation.original`.

**Native review.** Every translated page needs the §8 checklist before `reviewed: true`. Reviewer priorities (from the drafting notes): OS setting names in each language (Windows 11 "Power & battery"/battery saver naming, Android OEM app-sleep lists, macOS Lock Screen/Energy panes, iOS Auto-Lock "Never" in Hindi), keyword choices per `intent`, and the `downloads` pages, whose local head queries target system sleep while the product holds the display only.
